THE ROBOT
A reinforcement learning control system for a dual-arm ultrasound robot designed for
autonomous foetal imaging. The physical robot is a V3.4 dual-probe system with 17 motors,
22 joints (kinematics order), controlled by a Qt6 C++ app called USRobotControl. The goal
is to train the arms to autonomously position ultrasound probes on a maternal abdomen
without collisions.


PREVIOUS ITERATION ARCHITECTURE

Simulation stack:
- PyBullet         — physics engine
- Gymnasium        — standard RL environment interface
- SAC (Soft Actor-Critic) — off-policy RL algorithm, continuous action spaces + entropy regularisation
- URDF files       — define robot physical structure, joint limits, link geometry


TRAINING PIPELINE — CURRICULUM LEARNING (4 PHASES)

Phase 1 — Position-only, workspace expansion curriculum (2M steps)
  - Target zone expands from small sub-volume to full clinical geometry
    (15cm depth, 40cm sweep, 22cm vertical)
  - Episode length decreases 320 -> 250 steps (forces efficiency)
  - Success = closest end-effector within 0.05m
  - Terminal reward: +150

Phase 2 — Tolerance ramping 0.05 -> 0.04m (500k steps)

Phase 3 — Tolerance ramping 0.04 -> 0.02m (clinical target)

Phase 4 — Both arms must reach the same target simultaneously
  - Reward penalises the "bottleneck" arm (furthest from target)
  - Both arms must be within tolerance simultaneously
  - Terminal reward: +260

Reward function (two-arm):
  Rt = Rprogress - 0.02 - (0.5 x Ncollisions)
  Rprogress = (dmin,t-1 - dmin,t) x 100.0

HARDWARE INTEGRATION DESIGN (already built in previous iteration)
The RLInput C++ class acts as a TCP server (port 12345). The Python RL model sends JSON
{"joint_angles": [j0...j21]} messages. The app bypasses the IK solver (RL outputs joint
angles directly, not Cartesian poses) and applies joint limit + GJK collision checks
before sending to motors.

THE BIG PICTURE (WHY THIS ROBOT EXISTS)

An ultrasound probe has a small field of view. At a certain foetal age, the baby is too
big to capture in one image. The solution: a robot holding two probes simultaneously —
better field of view + overlapping images = better scan quality. The robot already
physically exists in the hospital lab (north wing). It has two arms, 17 motors total,
8 DOF per arm.
